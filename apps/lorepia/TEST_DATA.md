# LorePia 테스트 데이터

이 문서는 디자인과 화면 흐름을 반복 점검하기 위한 브라우저 데모 데이터의 구성과 사용법을 설명합니다.

## 실행

```bash
cd apps/lorepia
npm run demo
```

브라우저가 열리지 않으면 [http://localhost:5175/preview.html](http://localhost:5175/preview.html)에 접속합니다. 이 컴퓨터의 다른 개발 서버와 충돌하지 않도록 데모 포트는 5175로 고정했습니다.

데모는 `preview.html`에서만 활성화됩니다. 기본 앱 진입점인 `src/main.ts`와 Tauri 저장소는 데모 클라이언트를 가져오지 않습니다.

## 포함된 화면 데이터

| 화면      | 데이터                                                                     |
| --------- | -------------------------------------------------------------------------- |
| 홈        | 아리아, 카이, 세라, 노아 등 캐릭터 4명과 검색용 설명                       |
| 채팅 목록 | 아리아의 기존 대화 2개와 다른 캐릭터의 연결된 대화                         |
| 채팅방    | 본편 6개 메시지, 분기 대화, 날짜·마크다운·긴 문자열 점검 사례              |
| 생성      | 프롬프트 블록 4개, 제작자 컨트롤, 기억 2개, 지식, 작업 프로필, 콘텐츠 모듈 |
| 설정      | 제공자 템플릿 2개, 연결 1개, 모델 경로 1개, 생성 프리셋 2개, 카탈로그 기록 |
| 페르소나  | 여행자, 조사관, 작가 페르소나 3개                                          |

처음 열면 `아리아 → 잊혀진 서고 → 본편`이 미리 선택됩니다. 따라서 홈에서 목록을 확인한 뒤 별도 준비 없이 채팅·생성·설정 화면을 오가며 같은 문맥의 데이터를 비교할 수 있습니다.

## 동작과 초기화

- 캐릭터·대화·분기 선택은 실제 화면 컨트롤러를 통과합니다.
- 새 대화와 새 분기를 만들 수 있습니다.
- 채팅 입력 시 고정된 데모 답변이 추가됩니다. 외부 AI API를 호출하지 않습니다.
- 페르소나 추가·수정·삭제·선택은 현재 브라우저 세션 안에서 동작합니다.
- 설정의 생성 대상과 일부 생성 문서는 세션 안에서만 변경됩니다.
- 새로고침하거나 개발 서버를 다시 시작하면 모든 데이터가 원본 상태로 돌아옵니다.

데모 데이터에는 실제 API 키, 자격증명, 사용자 대화, 로컬 파일 경로가 없습니다. Tauri IPC, 운영 데이터베이스, macOS 자격증명 저장소에도 접근하지 않습니다.

## 파일 위치

- 데이터 원본: `src/preview/demo-data.ts`
- 상태형 데모 클라이언트: `src/preview/mock-client.ts`
- 데모 진입점: `src/preview/main.ts`
- 회귀 테스트: `src/preview/mock-client.test.ts`

## 데이터 추가 규칙

1. 화면에 필요한 DTO는 `demo-data.ts`에서 명시적인 타입과 고정 ID·시간으로 선언합니다.
2. 캐릭터, 대화, 분기, 메시지의 ID 참조가 서로 일치해야 합니다.
3. 반환값은 반드시 복제하여 한 화면의 수정이 원본 상수를 오염시키지 않게 합니다.
4. 새 화면 데이터를 추가하면 `mock-client.test.ts`에서 개수와 연결 관계를 함께 검증합니다.
5. 실제 사용자 정보나 운영 자격증명을 fixture로 복사하지 않습니다.

## 검증 명령

```bash
cd apps/lorepia
npm test -- src/preview/mock-client.test.ts
npm run check
npm run build
```
