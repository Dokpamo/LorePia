# 첨부 RisuAI 파일 사용 경로 구현·검증 — 2026-09-11

기준 커밋은 `15e559b`, Task는 `IMPORT-COMPAT-20260911`이다. 원본 파일 다섯 개를
해독하고 격리 저장소와 macOS `LorePia UI`에서 가져오기를 확인한 뒤, 발견한 연결
문제를 수정했다. 사용자는 대용량 모듈용 DB 저장 구조 변경도 승인했다.
원본 카드·프롬프트·스크립트 파일은 변경하거나 저장소에 복사하지 않았다.

가져오기, 설정 연결, 모듈 적용을 현재 UI에서 진행할 수 있게 했다. 실제 외부 모델의
답변·기억 요약·상태창 모델 호출은 아직 검증하지 않았다. 테스트 앱에는 선택할 수
있는 모델 연결이 없으며 사용자에게 사용할 서비스/모델을 문의한 상태다.

공통 진입점은 생성의 **파일 가져오기**다. 모델 연결은 **AI 연결과 모델**에서 등록한다.
원본에 포함된 모델 이름을 보고 임의의 외부 서비스나 자격 증명을 자동 선택하지 않는다.

## 수정한 원인

- `.risup`이 네이티브 임시 파일로 전달되면서 확장자가 사라져 프리셋 해독 경로에
  들어가지 못했다. staging이 `.risup`과 `.risum`을 보존하도록 수정했다.
- 기존 변환 도우미를 현재 설정 화면에 연결했다. 모델 응답 설정, 프롬프트 기본
  생성 설정, 요약 작업, 기억 프로필과 대화 설정을 각각 기존 IPC로 저장한다.
  최신 revision을 다시 읽고, 부분 저장 실패나 대화 전환을 성공으로 표시하지 않는다.
- 플러그인 목록 검증이 수천 개의 CAS 파일 핸들을 동시에 보유해 macOS의 파일
  디스크립터 한도에 걸렸다. 같은 핸들로 해시를 검증한 뒤 식별 증거만 보관하고,
  DB 스냅샷 비교 후 하나씩 다시 열어 식별 증거를 대조한다. 렌더러에 바이트를
  제공하는 기존 same-handle 검증 경로는 유지한다.
- Shell의 전체 검토 응답 한도와 Storage의 일반 JSON 한도 때문에 대용량 모듈을
  적용하지 못했다. 전체 권한을 검증한 후 검토 목록만 64개씩 보여주는 IPC 3개와,
  승인한 DB migration `0042`의 불변 문서 조각 저장을 추가했다.
- 네이티브 모듈 검증·적용과 대화별 표시 정보 조회를 제한된 blocking 작업으로
  옮겼다. 대화 복구를 동반하는 효과 이력 조회도 같은 경로를 사용한다. 조회는
  최대 8개만 받아 2개 worker를 공유하므로 일반적인 동시 화면 조회가 `busy`로
  탈락하지 않는다. 쓰기/승인의 즉시 admission과 승인·완료 상태 구분은 유지한다.
- 수천 개 구성 요소를 불러올 때 같은 부모 모듈을 매번 해독·검증하던 경로를
  일괄 조회로 바꿨다. 한 읽기 트랜잭션 안에서만 부모 검증을 공유하며 각 요청의
  source/component hash와 연결된 불변 리비전 검사는 유지한다.
- 설정 루트가 매번 모든 가져온 원본의 내보내기 검증을 실행하던 중복 초기 로드를
  제거했다. 가져오기/저장 공간 화면에서 필요한 때 기존 검증을 수행하고, 원본 목록
  조회도 bounded worker로 옮겨 화면 스레드에서 CAS lock을 기다리지 않게 했다.

저장 구조와 계약은 [large-module-activation-storage.md](../design/large-module-activation-storage.md)에
정리했다. 원본의 가져오기 제한, 일반 문서 한도, 런타임 권한, 정규식 실행 제한,
CAS 경로 및 자격 증명 경계는 유지한다.

## 검증 근거

- 원본 다섯 파일 모두 Core 검사·저장과 네이티브 파일 선택 UI 가져오기 성공.
- 실제 추가 에셋 파일의 격리 복제본: 전체 검토 3,173개, 응답은 64개씩, 전체 적용
  receipt 검증 성공. 기본 모듈을 추가한 3,175개 조합도 성공.
- 실제 앱 DB는 schema 42로 업그레이드됐다. 큰 review/approval/runtime 문서는
  각각 19/23/64조각으로 저장됐고 기존 카드·대화가 유지됐다. 추가 모듈의 적용 및
  비활성화는 UI의 검증된 완료 상태로 확인했다.
- 실제 파일의 격리 복제본을 다시 열어 카드와 추가 모듈을 합친 이미지 5,624개가
  대화별 Shell 표시 DTO까지 전달됨을 확인했다. 작은 카드의 표시 정보 조회도 통과했다.
- 최종 macOS 앱을 다시 실행해 해당 대화의 복원이 완료되고 한국어 시작 메시지가
  표시되는 것을 스크린샷으로 확인했다. 설정과 가져온 프롬프트 연결 화면의 즉시
  이동 및 모델 미등록 시 안내·저장 비활성도 확인했다. 이전 빌드에서 관찰한
  채팅의 `error.invalid_input`은 마지막 검증에서 재현되지 않았다.
- Core의 대용량 회귀 테스트는 1,024개 합성 에셋과 프롬프트를 정상 API로 적용하고
  Core를 재시작한다. 이후 새 브랜치와 다른 기존 대화에서 로컬 합성 provider로
  실제 generation dispatch를 수행해 프롬프트 반영과 완료된 응답을 확인했다.
- 문서 codec 테스트: 기존 inline 읽기, UTF-8 경계, 조각 재사용, 부모와 동일
  트랜잭션 rollback, 누락/순서/해시/길이 변조, 버전/깊이/용량/금지 키 거부.
- Shell 테스트: 513개 검토의 전체 페이지 일치, 오래된 페이지·위조 승인 거부,
  승인 응답 유실 후 같은 ID 재시도, 충돌 선택 필수.
- CAS 테스트: 128 FD 제한에서 512개 파일 검증, DB 스냅샷 변조, 동일 바이트로
  파일을 교체한 경우와 실제 바이트 변조 거부.
- 기존 실제 Lua 소스로 오프라인 입력·표시·출력 이벤트 및 언어/시스템 버튼 상태
  변경을 확인했다. 상태창의 외부 모델 호출은 켜지 않았다.
- 프런트엔드 전체 699개 테스트, 타입·Svelte·lint 검사 통과. Storage/Core/Shell/native
  대상 테스트, 스키마 신규 설치·업그레이드·과거 schema-11 cutover 회귀 통과.
  일괄 조회 후 Core 통합 14개와 child/source hash 불일치 거부, native worker 2개
  회귀 테스트를 다시 통과했다. 동시 조회 대기, 초과 요청 거부, 취소 후 반환도
  확인했다. 전체 workspace Clippy, format, IPC generator,
  source architecture 및 strict AI context 검사를 통과했다.
  임시 로그와 합성 테스트 도구는 `/tmp/lorepia-compat-audit-20260911`에 있다.

## 호환성의 범위

이 결과는 RisuAI의 모든 동작과 설정 조합이 동일하다는 뜻은 아니다.

- CHARX 변환 규칙 54개 중 5개는 유효성/실행 제한 검사에 따라 비활성화된다.
  기본 모듈은 142개 중 네이티브로 변환 가능한 115개와 원래 비활성 또는 비이식
  27개를 구분한다. 프리셋은 24개 중 19개와 5개를 구분한다.
- 가져온 원본과 격리 런타임 표현은 보존하며, 권한을 승인하지 않은 스크립트가
  임의의 모델 호출·네트워크·상태 쓰기를 수행하도록 허용하지 않는다.
- 추가 에셋 파일의 빈 `v2Header`를 실행 가능한 Lua 기능 하나로 세지 않는다.
- 카드 정보 미리보기에는 일부 Risu 조건식이 원문으로 보일 수 있다. 채팅에서
  실제 표시하는 경로와 별개이며, 모든 원문 미리보기 문법까지 바꾸는 작업은 하지 않았다.
- 외부 모델의 답변 품질, 상태창 생성, 하이파 요약 결과, 전체 151개 제어 항목의
  모든 조합은 실제 모델 연결 후 추가 검증이 필요하다. 임베딩 작업을 선택하지
  않으면 기억 요약은 연결할 수 있지만 벡터 유사도 검색은 활성화하지 않는다.
- 큰 모듈의 최초 권한·복원 검증은 unoptimized 개발 빌드에서 수십 초에서 수분
  걸릴 수 있다. 화면 스레드 차단과 구성 요소마다 부모를 반복 읽던 병목은 수정했으나,
  큰 원본 해시 및 실행 계획 검증 비용 자체를 제거한 것은 아니다. release 빌드의
  처리 시간은 별도 측정이 필요하다.

현재 화면의 선택/확정 패턴을 재사용했다. 선택 상태가 명확해야 한다는
[SEED Select Box](https://seed-design.io/react/components/select-box)와
문맥을 유지하는 [SEED Bottom Sheet](https://seed-design.io/react/components/bottom-sheet),
단순하고 일관된 사용자 경험을 설명하는
[토스 UI/UX 가이드](https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.html)를
참고했다. 색상·탭·아이콘 체계를 새로 만들지 않았다.
