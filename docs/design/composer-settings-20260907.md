# 입력바 전환과 설정 선택 UI 보완

2026-09-07 · 작업 ID `UI-COMPOSER-SETTINGS-20260907`

기존 `ChatComposer.svelte`, `ChatFullscreenComposer.svelte`, `composer-state.svelte.ts`와 관련 CSS·테스트를 비교해 격리된 Tauri UI 미리보기를 수정했다. 변경 범위는 입력바의 확장·축소, 확대 완료 후 버튼 배치, 설정 선택 UI다.

## 입력바

- 최종 입력 폭으로 줄 수를 측정하면서 실제 글자 영역의 좌우 이동 애니메이션을 중단하지 않도록 했다. 측정용 너비·패딩·높이는 화면이 그려지기 전에 복원한다.
- 창 크기 재측정은 `ResizeObserver` 안에서 바로 실행하지 않고 다음 프레임으로 합친다. 검증 중 개발 서버 로그에서 발견한 측정 중 재측정 문제를 방지한다.
- 입력바 높이와 글자 영역의 아래쪽 경계가 같은 시간과 곡선으로 움직인다. 기존에는 아래쪽 경계가 먼저 바뀌어 글자 영역이 잠시 잘렸다.
- 모바일에서는 포커스 시 작성 영역이 열리고, 두 줄부터 전체화면 버튼을 제공한다. 열 줄까지 자동으로 늘어나며, 그 이후 또는 남은 화면 높이가 부족할 때 내부 스크롤을 사용한다. 입력바 안의 버튼으로 포커스를 옮겨도 작성 영역을 유지한다.
- 전체화면 작성은 왼쪽 축소 버튼과 오른쪽 전송 버튼을 같은 줄에 둔다. 두 버튼의 터치 영역은 48px이며, 전송 버튼의 원형 표면은 입력바와 동일한 40px이다. 일반 필드 편집기의 제목·뒤로가기 배치를 분리했다.
- 전체화면 전환 중 글자의 시작 위치뿐 아니라 입력 폭도 이어지도록 했다. 확대된 채로 창 크기를 바꿔도 이전 폭에 고정되지 않는다.
- 축소 버튼과 Esc는 입력바 자리로 접힌다. 오른쪽 스와이프는 기존 제스처 뒤로가기를 유지한다. 일반 필드 및 보낸 메시지 편집의 취소 확인·필수 값 검증도 유지한다.

## 설정 선택 UI

화면 테마, 글자 크기, 응답 상태 선택에서 기본 `select` 팝업을 없애고 앱 안의 선택 목록을 사용한다. 모바일은 화면 높이의 70%를 차지하는 하단 팝업으로 열리고, 선택 목록은 제목 바로 아래부터 정렬한다. 맨 위 가로 손잡이는 72×44px 터치 영역으로 잡아 내릴 수 있다. 짧게 끌면 제자리로 돌아오고, 충분히 내리거나 빠르게 아래로 놓으면 닫힌다. 화면 아래에서 올라오고 다시 아래로 내려가는 300ms 전환은 드래그를 놓은 위치에서 이어진다. 하단 안전 영역을 확보하고 내용이 많으면 팝업 안에서 스크롤한다. 넓은 화면은 설정 영역 안에 내용 높이의 팝업으로 표시한다. 선택된 행은 중립 배경과 체크 표시를 사용한다.

현재 선택에 포커스를 두고 방향키·Home·End로 이동할 수 있다. 선택 전 Esc 또는 닫기로 나오면 값이 바뀌지 않는다. 닫은 뒤에는 원래 설정 버튼으로 포커스를 돌려준다. 앱 테마·글자 크기는 즉시 적용하고, 채팅방의 응답 상태는 기존 설정 저장·변경 폐기 흐름을 따른다.

대화 모드의 라디오와 서브페이지 스위치도 앱의 크기·색상 규칙으로 그린다. 피스타치오 주 버튼, 중립 선택 배경, 그림자 없는 표면과 기존 폴더 정리 방식은 유지했다. 폴더 묶기 버튼을 추가하지 않았다.

## 검증

- 선택 팝업 추가 조정(2026-09-08): 394×854px와 320×568px에서 높이가 화면의 70%이고 하단 간격은 0px임을 확인했다. 작은 화면에서도 모든 선택지가 잘림 없이 표시되며 밝은 테마 전환과 글자 크기 팝업을 확인했다.
- 손잡이 추가 조정: 제목 아래 첫 선택지 간격 16px, 손잡이 터치 영역 72×44px을 확인했다. 브라우저와 Tauri에서 짧은 드래그는 복귀하고 긴 드래그는 닫힌다. 드래그를 놓은 뒤 패널의 y좌표가 506→533→558→584px로 이동해 중간에 원래 위치로 튀지 않았고, 닫기 버튼도 화면 아래로 내려간다. 포인터 취소·두 번째 터치·리사이즈·해제 후 이벤트 정리·축소된 UI 좌표·키보드 닫기를 테스트했다.
- 320×568px에서 열 줄 입력: 입력 높이·스크롤 높이 모두 264px, `scrollTop=0`.
- 입력바 확대의 중간 프레임: 글자 영역 높이가 48px에서 34px로 연속적으로 바뀌며 일시적으로 잘리지 않음. 좌우 이동도 유지됨.
- 394px 전체화면: 축소 버튼 x=20/y=16, 전송 버튼 x=326/y=16, 둘 다 48×48px. 전송 표면은 40×40px.
- 1440px 전체화면: 입력 내용 폭 760px, 작은 화면으로 바꾸면 346px로 재배치. 확대 중 글자와 버튼의 이동, 버튼·Esc 축소의 중간 프레임을 확인함.
- 320px·394px에서 밝은/어두운 선택 목록과 큰 글자 배치, 키보드 선택·닫기·포커스 복귀를 확인함. 개발 서버 로그의 `ResizeObserver` 알림 충돌 기록을 추가 확인해 재측정 일정을 수정하고 회귀 테스트를 추가함.
- 수정 후 입력 중 및 전체화면 상태에서 320·394·760·1120·1440px 사이의 크기 변경을 다시 수행함. 새 개발 서버 로그에서 같은 알림 충돌은 발생하지 않았고, 축소 후에도 열 줄 입력을 모두 표시함.
- Tauri 창에서 확대 완료 후 배치, 실제 축소 버튼 클릭·Esc와 작성 초안 보존을 확인함. 새 설정 선택 목록도 앱에서 열어 확인한 뒤 기존 설정 화면으로 복원함.
- UI 테스트 18개 파일·150개 테스트 통과. 프론트엔드 검사 통과, 기존 `ChatPane.svelte` 경고 2개 유지.
- UI 프로덕션 빌드 및 Tauri 디버그 앱 번들 빌드 통과.
- 아키텍처 검사는 변경 전후 동일한 기존 Core 공개 API 진단 75개. 크기 기준을 상향하지 않았다.

변경은 메모리 샘플 UI에 한정된다. Rust·IPC·라이브 렌더러·의존성·스키마를 변경하지 않았다. 실제 모바일 소프트 키보드와 보조 기술은 이번 검증에 포함하지 않았다. 작업 전 파일 사본과 해시는 `/tmp/lorepia-composer-settings-20260907/`에 기록했다.
