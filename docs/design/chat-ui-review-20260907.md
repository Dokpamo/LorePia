# 채팅방 UI·UX 비교 검토

후속 구현과 실제 조작 검증은
[UI-CHAT-COMPLETE-20260907](ui-chat-complete-20260907.md)에 기록했다.
아래는 구현 전 상태에 대한 검토 기록이다.

현재 시안은 입력바의 줄 수 측정과 전체화면 작성 동작을 일부 가져왔지만,
기존 채팅방의 배치 계산, 읽던 위치 유지, 메시지 작업과 응답 상태는 충분히
옮겨지지 않았다. 다음 구현은 하단 배치 → 스크롤과 메시지 메뉴 → 응답 상태
순서로 진행하는 것이 적절하다.

- 검토일: 2026-09-07. Task ID: `UI-CHAT-REVIEW-20260907`.
- 비교 기준: GitHub `Dokpamo/LorePia`의 `main`, 커밋
  [`ba5fd685159df1a1533d7054d7b2e01d3b267202`](https://github.com/Dokpamo/LorePia/tree/ba5fd685159df1a1533d7054d7b2e01d3b267202).
  원본 10개 파일을 직접 읽고 로컬의 변경 중인 시안과 비교했다.
- 원본 범위: `ChatPane`, `ChatComposer`, `ChatFullscreenComposer`,
  `composer-state`, `ChatMessageList`, `ChatMessageActions`, `message-actions`,
  `chat-scroll`, `PortableMessage`, `styles/chat/chat.css`.
- 실행 확인: 브라우저의 모바일·넓은 화면과 macOS Tauri UI 미리보기.
  iPhone/Android 실기기 키보드 동작은 이번 검토의 실행 확인 범위에 포함되지 않는다.
- 이 문서는 검토 결과다. 아래 채팅방 보완 사항은 아직 구현 완료된 것이 아니다.
  별도로 요청된 뒤로가기 모션과 창 축소 비율 수정은 각 작업 문서에 기록했다.

## 1. 하단 버튼이 입력바 뒤로 가려짐 — 실제 배치 오류

사용자가 보낸 화면에서 ‘최근 메시지’ 버튼의 아래쪽이 입력바에 가려진다.
현재 `.ui-jump-latest`는 높이가 0인 컨테이너이고, 안의 48px 버튼은 아래로
뻗는다. 뒤에서 적용되는 composer CSS가 기존 위쪽 이동을 `transform: none`으로
취소한다. 입력바와 버튼의 z-index도 같아 뒤에 그려지는 입력바가 버튼을 덮는다.

현재 근거: `ui-editing.css:157`, `ui-composer.css:162`.
시안의 `composer-measure.ts:71`은 입력 필드 높이만 공통 값으로 저장한다.
원본 `composer-state.svelte.ts:213`은 필드 높이, 실제 하단 inset, 전체 덮는
영역의 높이를 따로 계산해서 본문과 전체화면 전환에 제공한다.

보완: 입력 필드의 위쪽 좌표를 기준으로 최근 메시지 버튼의 아래쪽을 배치하고,
본문 끝 여백도 같은 측정값에서 계산한다. 1→2→10줄, 창 폭 변경, 하단 안전 영역
변경 중에도 버튼과 입력바 간격이 유지되어야 한다.

## 2. 메시지 메뉴가 갑자기 끼어들고 읽던 위치를 유지하지 않음

현재 `ChatTranscript.svelte:81`은 메뉴를 조건부로 바로 추가한다. 메뉴 자체의
펼침 전환이나 선택 메시지를 기준으로 하는 위치 보정이 없다. 기존 원본은
`MessageActionsState.activate()`에서 `stabilizeMessageActionLayout()`을 호출하고,
모바일 메뉴 높이·간격·투명도를 함께 전환한다.

원본 근거: `message-actions.svelte.ts:36`, `chat-scroll.svelte.ts:191`,
`styles/chat/chat.css:716`. 현재 근거: `ChatTranscript.svelte:74`,
`ui-editing.css:150`.

보완: 메뉴 펼침과 본문 스크롤 보정을 하나의 동작으로 구성한다. 복사와 사용자
메시지 편집뿐 아니라 원본의 분기, 재생성, 삭제 확인, 생성 중 제한 상태도
새 프레임 안에서 위치와 노출 방식을 정해야 한다. 아이콘의 시각 크기와 터치
가능 영역은 별도로 정해 충분한 터치 영역을 유지한다.

## 3. 긴 대화와 창 폭 변경을 다루는 스크롤 처리가 빠짐

시안은 모든 메시지를 순서 인덱스로 렌더링하고, `scroll` 이벤트와 메시지 수
변화에 주로 의존한다. 입력바 높이 변화에 대한 일부 보정은 있지만, 폭 변경으로
문장 줄바꿈이 달라질 때 읽던 메시지를 유지하는 원본의 동작까지 포함하지 않는다.

원본 `ChatScrollLifecycle`은 메시지 ID, 높이 측정, 가상 목록, 읽던 위치의
기준 메시지를 함께 관리한다. 로컬 원본 테스트에는 10,000개 메시지의 DOM 수 제한,
폭 변경 시 읽던 위치 유지, 삭제 후 위치 유지, 화면 높이 변경 시 맨 아래 여부
갱신, 가상 목록에서 사라지는 요소의 포커스 인계가 명시되어 있다.

근거: `chat-scroll.svelte.ts:120`, `ChatPane.scroll.test.ts:112`, `:184`,
`:303`, `:468`, `:662`. 현재 근거: `ChatTranscript.svelte:21`, `:54`, `:58`.

보완: 실제 기능에 연결할 때 기존 컨트롤러의 스크롤 소유권을 살리고 새 화면을
연결한다. 긴 대화를 읽다가 입력하거나 메뉴를 펼칠 때, 마지막 메시지를 보고
있을 때를 구분해 검증해야 한다.

## 4. 완료된 일반 텍스트 외의 채팅 상태가 아직 설계되지 않음

시안의 `UiPreview.send()`는 로컬 사용자 메시지를 배열에 추가하며,
`ChatTranscript`는 문자열을 문단으로 표시한다. 실제 생성 연결이 없는 시안의
범위지만, 이 상태만으로 채팅방 디자인이 완성됐다고 판단할 수는 없다.

원본은 스트리밍 답변, 추론 표시, 미완료 메시지 상태, 생성 중 작업 제한,
재생성과 분기, `PortableMessage` 콘텐츠를 다룬다.
근거: `ChatMessageList.svelte:202`, `:236`, `ChatMessageActions.svelte:38`.
현재 근거: `UiPreview.svelte:198`, `ChatTranscript.svelte:77`.

보완: 응답 시작·생성 중·중단·실패·재시도 상태, 긴 서식 본문과 제작자 콘텐츠가
있는 메시지까지 같은 프레임에서 배치한다. 기존 Rust/IPC 계약과 콘텐츠 표시의
보안 경계는 유지한다.

## 유지할 부분과 추가 확인

주황 강조색, 평면적인 SVG 버튼, 연결된 세 페이지, 2줄부터 확장·일반 높이에서
10줄까지 자동 증가하는 현재 요구사항은 유지한다. 원본의 코드에서 확인된 것은
2줄 이상에서 전체화면 버튼을 표시하는 조건과 화면 높이에 따른 입력 영역 제한이다.
원본 수치를 그대로 적용하면 현재 사용자가 정한 10줄 정책과 달라질 수 있다.

현재 시안에도 줄 수 측정, WebKit 입력 스크롤 보정, 원래 위치에서 전체화면으로
커지는 전환, 초안 유지가 있다. 이 부분까지 미구현이라고 평가하지 않는다.
다만 날짜·발화자·메뉴 행의 간격은 실제 긴 대화와 응답 상태를 넣은 뒤 밀도를
조정할 필요가 있다. 메시지 하나뿐인 화면의 빈 공간 자체는 결함으로 보지 않는다.

키보드에 따른 화면 변화는 실제 iOS/Android에서 추가 확인해야 한다. 원본도
이번에 읽은 범위만으로 모든 키보드 대응이 검증됐다고 단정할 수 없다.
