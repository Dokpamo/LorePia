[앞선 검토](seed-ui-review-20260907.md)의 입력 보존, 결과 안내, 누름 반응, 가독성, 검색과 도구 안내를 구현했다. 좌측 관리·중앙 채팅·선택형 우측 페이지, 그림자 없는 표면, 중립 선택 표시와 주요 확정 버튼의 피스타치오는 유지했다.

## 재점검하며 함께 고친 부분

- 검색 결과를 선택한 뒤 닫힌 편집기를 열었던 이전 버튼으로 포커스가 돌아갈 수 있었다. 이제 화면 전환이 끝난 다음 선택한 대화 내용에 포커스를 둔다.
- 복사 재시도로 안내가 교체되거나 닫기 버튼이 사라질 때 키보드 포커스가 유실될 수 있었다. 대화 내용으로 돌려주고, 이미 떠난 대화의 늦은 복사 결과는 무시한다.
- 성공 안내는 포인터가 떠나도 키보드 포커스가 남아 있으면 유지한다. 반대 경우도 동일하게 처리한다.
- 응답이 계속 들어오는 중에도 전체 대기 시간만으로 지연 안내가 나올 수 있었다. 이제 새 텍스트가 들어오면 지연 타이머를 다시 시작한다.
- 브라우저에서 편집기를 제거하는 순간 발생하는 `focusout`이 도움말 상태를 렌더 도중 바꿔 런타임 오류를 만들었다. Svelte 이벤트 API로 처리하고, 제거 시에는 구독과 연결만 해제한다. 해당 브라우저 동작을 재현하는 회귀 테스트를 추가했다.
- 변경 폐기 확인창의 중립 버튼이 눌릴 때 피스타치오로 바뀌지 않도록 누름 색도 중립 토큰으로 맞췄다.

## 남아 있는 검증과 연결 작업

**실제 데이터 상태 연결:** 이 앱은 `ui-preview.html`의 메모리 샘플이다. 응답 상태의 표현을 구현했지만 실제 Core의 로딩·가져오기·저장 오류에 연결한 것은 아니다. 라이브 화면에 통합할 때 기존 컨트롤러의 상태와 정확히 대응시켜야 한다. 미리보기에 생산 데이터나 IPC를 연결하지 않는 프런트엔드 경계를 유지했다.

**실기기 사용감:** 브라우저 폭 조절과 macOS Tauri 확인으로 iOS·Android 소프트 키보드, 가장자리 뒤로가기와 OS 제스처 충돌, 안전 영역, VoiceOver·TalkBack까지 검증했다고 볼 수 없다. 다음 확인은 실제 모바일에서 긴 입력·키보드 열림·큰 글자·제스처 취소를 함께 사용하는 것이다. APCA와 프레임 시간 프로파일링도 아직 수행하지 않았다.

기준 커밋은 `6f22761a4305443541452e7409639114f4c10dfd`이며, 앞선 피스타치오 변경과 다른 작업의 수정 내용은 보존했다. 이번 반영 범위는 미리보기 UI, 해당 한국어 문구, 관련 테스트와 이 검토 문서다.
