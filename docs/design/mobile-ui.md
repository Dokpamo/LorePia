# LorePia 모바일 제품 설계

Task: `MOBILE-PRODUCT-REDESIGN-20260906`

## 출발점

사용자가 원하는 일은 캐릭터와 이야기하고, 그 이야기를 이어가고, 필요할 때
대화의 조건을 바꾸는 것이다. Rust의 기능과 데이터가 제품의 근거이며 이전
웹 화면의 메뉴 순서, 카드, 프로필 모양은 설계의 근거로 삼지 않는다.

토스의 쉬운 말, 명확한 다음 행동, 가치 먼저 보여주기 원칙을 적용한다.
금융 기능이나 가상의 계정·사용자 정보를 추가하지 않는다.

## 화면 배치와 이동

| 화면 | 위에서 아래로 배치 | 첫 번째 행동 |
| --- | --- | --- |
| 홈 | 브랜드·검색 → 대화 시작 안내 → 이어갈 대화 → 캐릭터 목록·추가 | 캐릭터를 눌러 대화 열기 |
| 대화 | 제목·검색 → 캐릭터 필터 → 최근 순 대화 기록 | 기록을 눌러 이어가기 |
| 전체 | 제목 → 대화 환경 → 이야기 만들기 → 앱 설정 → 모델 관리와 도구 → 앱 버전 | 목적에 맞는 설정 열기 |
| 대화방 | 뒤로·캐릭터 이름·대화 도구 → 본문 → 입력·보내기 | 메시지 보내기 |
| 상세 | 뒤로 → 큰 제목 → 선택/입력 → 필요한 경우 하단 저장 | 한 가지 설정 완료하기 |

하단 탭은 홈·대화·전체 세 개다. 제작 도구는 전체에서 찾아 들어간다.
상세 화면에는 하단 탭을 표시하지 않으며 뒤로 가기는 항상 한 단계씩 이동한다.
대화방 설정은 AI와 답변·기억과 세계관·캐릭터 표현·대화 방식으로 나누며,
제작자가 제공하는 조절 항목과 지원되는 기능만 표시한다. 기존의 닫을 때 저장하는
동작을 유지하고 화면 안에 이 동작을 안내한다.
검색은 현재 목록을 좁히고, 취소하면 목록과 검색 버튼의 포커스를 복원한다.
홈에서 불필요한 프로필·통계·중복 버튼을 제거한다. AI가 선택되지 않은 경우에만
연결 안내를 보여준다. 캐릭터는 기존의 선택/대화 열기 규칙을 그대로 따른다.

## Rust 기능과 화면의 연결

| 지원 기능 | 새 모바일 진입점 | 기존 소유자 |
| --- | --- | --- |
| 캐릭터 조회·검토 후 가져오기 | 홈의 목록·추가 | Shell API library, library/import controller |
| 대화 조회·열기·생성·분기·메시지 | 대화 목록·대화방 | Shell API conversation/generation, chat controller |
| 연결·키·모델·프리셋 선택 | 전체 → 대화 환경 | Shell API provider, provider controller |
| 페르소나 조회·편집·선택 | 전체 → 대화 프로필 | Shell API persona, persona controller |
| 프롬프트·기억·지식·실행 규칙 | 전체 → 이야기 만들기 | Shell API orchestration, orchestration controller |
| 콘텐츠 패키지·모듈 | 전체 → 콘텐츠 관리 | Shell API package/module lifecycle, content controllers |
| 탐색·동기화·템플릿·카탈로그·진단 | 전체의 목적별 도구 | 기존 기능 controller |

API, DTO, 저장 구조, 스트림·취소·복구·승인 규칙은 변경하지 않는다.
이미지는 CharacterAvatar/TrustedAsset의 승인된 자산 경로로만 표시한다.

## 시각 규칙

- 모바일 전용 색상과 컴포넌트를 사용한다. 공통 상세 컨트롤에도 같은 색상을 전달한다.
- 밝은 화면은 차가운 회색 바탕과 흰 면, 어두운 화면은 검은 바탕과 진회색 면이다.
- 파랑은 실행·선택에 사용한다. 배경 그라데이션과 장식용 그림자는 사용하지 않는다.
- 393px 기준 바깥 여백 20px, 카드 안쪽 20px, 카드 간격 16px, 둥근 모서리 24px.
- 큰 제목 28px, 카드 제목 19px, 주요 행 17–18px, 보조 설명 14–15px.
- 최소 터치 영역 44px. 목록은 72–92px, 입력·저장은 52–56px.
- 긴 설명은 두 줄까지 보여준다. 선택값이 긴 행은 줄바꿈하며 가로 스크롤을 만들지 않는다.
- 하단 고정 영역과 키보드를 고려해 마지막 항목까지 스크롤할 수 있어야 한다.
- 빈 목록·불러오는 중·실패 상태는 실제 상태에 맞는 다음 행동을 제공한다.
