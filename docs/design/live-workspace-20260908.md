# 목업 기반 실사용 UI 연결

사용자가 승인한 목업을 메인 화면으로 사용한다. 왼쪽 캐릭터·채팅 내역,
중앙 채팅, 선택형 오른쪽 제작자 페이지의 배치와 SVG 아이콘, 중립 선택색,
피스타치오 전송 버튼, 입력바의 크기·확장·전체화면 편집 동작을 공유한다.
새 기능을 연결할 때 옛 App 화면을 다시 메인으로 사용하지 않는다.

## 진입점과 소유권

- `apps/lorepia/src/main.ts` → `app/workspace/WorkspaceApp.svelte`가 실사용 진입점이다.
  Tauri UI 빌드는 `workspace.html`을 연다.
- `src/ui/workspace`는 목업에서 승격한 표시·제스처·편집 컴포넌트다.
  `src/preview/ui`는 같은 컴포넌트를 고정된 예제 데이터로 검증한다.
- 실사용 화면은 하나의 IPC client와 `LorepiaAppController`를 공유한다.
  저장, 요청 경합, 스트림 검증, 취소, 분기와 재연결의 기존 소유권을 유지한다.
- 카드·채팅·메시지는 Rust DTO를 표시 모델로 투영한다. 빈 저장소에 예제
  캐릭터나 생성 응답을 주입하지 않는다.
- 이미지에는 기존 `CharacterAvatar` → `TrustedAsset` 경로를 사용한다.
  `avatar_asset_id`의 내용 주소는 digest selector로 조회하며 검증을 우회하지 않는다.
- 제작자 마크업, 변수, 모델 실행과 상호작용에는 기존 portable/runtime 및
  interaction lifecycle을 사용한다. 기존 grant·sanitizer·sandbox 경계를 유지한다.
- 실사용 진입점은 옛 기능 패널의 CSS를 불러오지 않는다. AI·데이터·런타임
  설정은 기존 controller를 목업의 SettingsPanel·SettingsRow·ChoiceSheet와
  전체화면 TextEditor로 연결한다. 목업과 같은 제목·그룹·행의 배치를 사용한다.

## 연결된 동작

- 네이티브 파일 선택 → 가져오기 검토 → 카드 저장 및 이미지 표시
- 카드별 채팅 내역, 첫 메시지 선택, 새 대화 생성, 기존 대화 열기
- 채팅/스토리 모드 저장, 메시지 전송·취소, 기존 메시지 편집·분기·재생성·삭제
- 승인된 생성 시도의 재시도, 상호작용 화면과 제작자 런타임 제어
- 앱 설정과 AI 연결·모델, 프롬프트·페르소나 등 기존 설정 controller 연결

전체화면에서 저장 실패 시 편집 내용을 유지한다. 전송 실패, 늦게 도착한
전송 확인, 대화 전환 때문에 새 입력이 지워지지 않도록 확인한다.

## 검증과 현재 범위

네이티브 개발 앱에서 검증용 CHARX 두 개를 직접 가져오고 첫 대화를 만들었다.
앱을 종료한 후 다시 열어 카드 이미지, 대화와 스토리 모드의 복원을 확인했다.
기본 모델이 없을 때 전송이 차단되고 입력이 남는 것도 확인했다.
최종 네이티브 화면에서 저장공간의 카드·대화·메시지 수, AI 설정 진입,
채팅 모드 저장, 첫 메시지에서 새 분기 만들기, 두 줄 입력바 확장 및
전체화면 작성의 전송·축소 버튼 위치를 확인했다. 확인용 입력은 지웠다.
실제 외부 AI 응답은 사용자가 API 연결을 등록한 뒤 확인해야 한다.

가져온 원본 카드 정보는 읽기 전용이며 수정한 원본은 다시 가져온다.
카드 폴더 정리는 현재 화면 상태이고 Rust의 폴더 저장 API는 추가하지 않았다.
첫 greeting 메시지 분기의 checkpoint 오류는 저장된 greeting 출처와 첫
대화 이벤트를 검증하는 경계 처리로 수정했다. 생성 이력이 있으면 정확한
과거 스냅샷을 사용하고, 이력이 없을 때만 검증된 초기 경계를 사용한다.
이력 손상이나 누락을 현재 상태로 대체하지 않는다. Core 회귀 3개와 Storage
상호작용 검사 32개, 해당 크레이트의 clippy 및 Rust 포맷 검사가 통과했다.

프런트엔드는 119개 파일의 900개 테스트와 portable Lua·regex sandbox 회귀,
format·i18n·lint·typecheck, 소스 아키텍처 검사가 통과했다. typecheck의
경고 2개는 실사용 진입점에서 사용하지 않는 이전 ChatPane의 controller
초깃값 캡처에 관한 기존 경고다.

## 글자와 배치 기준

목업과 실사용 화면은 같은 토큰을 사용한다. 기본 배율의 글자는 화면 제목
22px, 섹션 제목 20px, 내비게이션 18px, 본문 17px, 보조 설명 15px,
캡션 13px이다. 화면 제목의 행간은 약 31px, 본문은 25.5px이다.

SEED의 [Typography](https://seed-design.io/foundations/typography)는 크기·행간·굵기를
역할별 스타일로 묶고, [Spacing](https://seed-design.io/foundations/spacing)은
화면 가장자리·텍스트 사이·컴포넌트 사이를 용도별 간격으로 정의한다.
SEED의 화면 제목 26/35px·700 및 게시글 본문 16/24px·400은 참고값이다.
이번 연결 작업에서 승인된 목업의 글자 크기를 그 값으로 바꾸지는 않았다.
다음 위계 조정에서는 제목과 섹션 제목의 차이, 긴 안내 문장의 보조 설명
처리, 주 행동과 보조 행동의 강조 차이를 함께 검토한다.

## 설정 탐색과 뒤로가기

설정 목록은 하위 페이지를 열어도 마운트된 채로 유지한다. 가려진 페이지는
inert와 aria-hidden으로 입력·포커스에서 제외하고, 새 페이지는 오른쪽에서
들어온다. 뒤로가기는 바로 이전 설정 페이지를 드러내며 오른쪽으로 나간다.
상위 설정을 다시 생성하거나 채팅 내역을 중간 화면으로 사용하지 않는다.
AI 연결·모델·프리셋·탐색·동기화의 상세 편집과 패키지 가져오기도 같은 구조다.
채팅방·카드 설정에서 AI 또는 프롬프트로 들어갔을 때는 호출한 설정으로 복귀한다.

한 이동이 끝나기 전 반복한 뒤로가기 버튼·Escape·트랙패드 입력은 중복으로
적용하지 않는다. 이동 중 화면을 다시 잡으면 취소된 애니메이션의 완료 처리는
무시하고 현재 손 위치에서 이어간다. 가려지거나 제거된 페이지의 늦은 완료도
다른 페이지를 닫지 못한다. 짧은 드래그·취소·동작 줄이기 설정을 검증한다.

회귀 검사에서 상위 설정의 DOM·스크롤을 유지하고 캐릭터 이미지 요소·주소·
ready 상태·조회 횟수가 탐색 전후 동일함을 확인했다. 네이티브 앱에서는
설정 → 플러그인 → 패키지 화면의 진입·버튼 복귀·제스처 복귀·짧은 드래그
취소를 직접 확인했다. 해당 수정 후 프런트엔드 122개 파일의 919개 테스트와
소스 아키텍처 검사가 통과했다.

기존 개발 저장소는 시작 시 generation recovery 오류가 있었고 카드·대화·모델
연결은 비어 있었다. 원본 전체를 `LorePia Development.before-ui-connection-20260908`
디렉터리로 보존하고 파일 해시 일치를 확인한 뒤 정상 초기화를 검증했다.
원본 데이터베이스나 migration을 직접 수정하지 않았다.

## 실행

저장소에 고정된 Node와 Rust 버전을 사용한다.

```sh
npm run tauri:ui --prefix apps/lorepia
npm run tauri:ui:build --prefix apps/lorepia
```

회귀 검사는 `src/preview/ui`, `src/app/workspace`, `src/ui/workspace`와 기존
portable runtime·IPC·Tauri window 검사를 사용한다.
